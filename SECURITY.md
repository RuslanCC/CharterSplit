# Безопасность

## Как сообщить об уязвимости

Пожалуйста, **не создавайте публичный issue**. Отправьте отчёт приватно через
[GitHub Security Advisories](https://github.com/RuslanCC/CharterSplit/security/advisories/new)
(вкладка *Security* → *Report a vulnerability*).

Опишите проблему, шаги воспроизведения и возможное влияние. Мы подтвердим получение,
разберёмся и выпустим исправление; автора отчёта упомянем, если он не против.

## Модель безопасности

- Аутентификация — только подписанный Telegram `initData` (HMAC с токеном бота, проверка срока).
- Ключ поездки берётся из подписанных данных; вступление по ссылке `startapp=c<chatId>`
  требует членства в этом чате (проверяется через Bot API).
- Вебхук защищён секретом в пути и заголовке `X-Telegram-Bot-Api-Secret-Token`.
- Секреты (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, пароль БД) живут только в `.env`,
  который не попадает в git; секрет вебхука и `initData` вырезаются из логов.

Если вы разворачиваете свою копию: держите `.env` с правами `600`, используйте длинный
случайный `TELEGRAM_WEBHOOK_SECRET` и не публикуйте порт PostgreSQL наружу.
